# A7 deletion impact and release authorization

Production deletion execution is disabled. A super administrator can confirm a request for review. This does not remove data. The execution endpoint operates only after the dedicated E2E database and schema guards pass and the subject is a synthetic E2E mother.

## Ownership and proposed impact

| Data | Production inventory and proposed handling |
| --- | --- |
| Account | Keep the technical user ID for request references. Remove the name, username, email, password credential, verification status, and last activity. Disable login and revoke sessions. Review whether retained account IDs and linked metadata are permitted under the approved retention policy. |
| Profile and recovery | Remove `mother_profiles`, `recovery_contexts`, `body_checks`, `sleep_logs`, `walk_logs`, and `exercise_sessions` scoped by user ID. |
| Wellbeing and journals | Remove `wellbeing_schedules`, `wellbeing_checkins`, `activity_sessions`, and `journal_entries` scoped by user ID. |
| Nutrition and tracking | Remove `food_logs`, `favorite_foods`, `hb_records`, `hydration_logs`, `weekly_reports`, `meal_plans`, and its `meal_plan_items`. Delete child items before parent plans. Meal-plan items can also reference food logs. Refuse cross-account links before processing. |
| Dashboard | Remove `dashboard_todos` and `dashboard_reminders` scoped by user ID. |
| Conversations | Remove `chat_feedback`, `chat_messages`, and `chat_sessions` in child-first order. Reject an unexpected cross-account feedback link. |
| Account links and exports | Remove reset and verification token rows. Revoke export tickets, clear export references, and remove corresponding private ZIP files. E2E executes filesystem removal after the committed database work. Production requires a durable cleanup and retry policy. |
| Request and audit history | Keep only the technical request/account IDs, administrative decision metadata, and timestamps under an approved retention schedule. Existing audit rows require a review for historical free text before production release. |
| Financial and subscription records | No payment or subscription tables were found in the inspected schema. Inventory any external providers and approve the retention and separation policy before enabling production execution. |
| Photos and other files | No mother-owned persisted photo table or upload path was found. The nutrition scanner processes uploads without a stored photo record. Admin Media Library files are shared editorial assets. Verify deployment storage, backups, and any external processors before production release. |

The impact API returns counts only. Processing stops if live ownership foreign keys differ from the inventory. The test execution path also refuses unsynthetic accounts and unexpected cross-account feedback references.

## Required production decision

Before enabling irreversible deletion, approve the retention and erasure policy for backups, exports, audit records, financial records, external processors and account tombstones. Approve the specific deletion runner and reconciliation of file removal, then require separate explicit authorization for production execution. Verify that any deployment-specific tables, paths, and in-flight writers are covered.

## Account email and exports

Configure `ACCOUNT_EMAIL_FRONTEND_ORIGIN`, `ACCOUNT_SMTP_HOST`, `ACCOUNT_SMTP_FROM`, and optionally `ACCOUNT_SMTP_PORT`, `ACCOUNT_SMTP_USER`, and `ACCOUNT_SMTP_PASSWORD` through private deployment configuration. Email delivery uses STARTTLS. Confirm SPA routing serves the reset and verification pages. The current application records last active time at successful mother login and has no subscription plan source.

Production exports are stored in the service account's local private HerBloom directory. Restrict filesystem access to that account and explicitly approve file retention and disposal before production use. Export access expires within 24 hours and requires an authenticated, single-use ticket generated by the confirming super administrator. Download expiry does not itself erase the ZIP from disk.


## Default-off production gates

- `A7_EXPORTS_ENABLED` controls export confirmation, ZIP generation, ticket issuance, and download redemption. Disabling it also blocks downloads of existing exports. Support can still open export requests.
- `A7_OUTBOUND_EMAIL_ENABLED` controls administrative reset and verification token issuance, public reset scheduling, and SMTP transport. When off, public reset requests still return the same generic response.
- Both flags accept only `true` (case-insensitive, surrounding whitespace ignored). Missing, empty, false, or invalid values resolve to off. Setting SMTP credentials alone cannot enable sending. E2E loads settings from its private profile and does not use production provider credentials.
- Leave both flags off when restarting production. Approve and verify storage permissions, retention, and cleanup before enabling exports. Separately verify STARTTLS and recovery routing with a test sink before enabling email. The production deletion guard is independent of both flags.
