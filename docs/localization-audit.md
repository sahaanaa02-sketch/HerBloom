# HerBloom localization audit

## Scope

The baseline covers 110 active frontend source files under `frontend/src`. The inventory records 962 static candidate occurrences (834 distinct texts). Recorded line numbers refer to the pre-edit source. Each occurrence is counted once, even when it shares a translation key with another occurrence.

Static coverage includes JSX text, accessibility and form attributes, selected object properties, direct state feedback calls, and simple conditional strings. CSS and JSON files are included in the source scope. The AST scan excludes archived backup copies, tests, and existing translation resources from UI findings. It cannot prove coverage of composed expressions, translated props, arrays, or user-visible API responses.

## Results

- **Open** 0
- **Resolved** 729
- **Exception** 40
- **Delegated** 152
- **Clinical** 41

The post-edit scanner found 287 candidates, including already localized label sources, bilingual branches, official names and clinical copy. Of the 627 previously open occurrences, 565 were resolved in source, 40 were confirmed already localized, 5 were classified as intentional exceptions, and 17 were moved to clinical review.

## Runtime audit still required

Admin Media Library now maps documented file-type, size, invalid-content, missing-file, and archived-file details into Tamil and English. Unknown diagnostics use an operation-specific fallback.

- Trace dynamic keys and labels derived from enums, especially Admin safety, subscriptions, review states and notification filters.
- Inspect errors sent by Admin and Mother endpoints. Map stable codes or known safe messages and use translated fallbacks for unexpected diagnostics.
- Verify browser-native validation, interpolated copy, nested dialogs, and empty or unauthorized states.
- Preserve user-entered content and independent AI response and Admin preview language selectors.

accounts and repeat each scenario at desktop width and 390 px, in English and Tamil.

| Surface | Steps and expected evidence |
| --- | --- |
| Landing and sign-in | Switch language, check headings, footer, FAQ and validation, then refresh. Open sign-in and switch while typing. The URL and input should survive and the document language should match. |
| Recovery and onboarding | Submit invalid input and step through a synthetic account with optional answers. Switch languages mid-step and verify inputs, canonical option values and progress remain intact. |
| Mother Portal | Exercise each form, empty state and confirmation. Change language in Profile Settings, Wellbeing, and Learn and Care. Refresh and log in again to verify the saved preference. In AI Chat, change response language and verify the UI language remains fixed. |
| Admin Portal | Check each module's filters, dates, tables, form errors and confirmations. Switch UI language with edits pending and verify the form remains intact. Change preview language independently. |
